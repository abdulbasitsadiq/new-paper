# `shared-resources/` — the analysis engine

This is a **plain folder, not a Quarto project** (there is no `_quarto.yml` here and
nothing renders here). It is where the heavy, slow work happens **once**: cleaning
data, running statistics, and generating figures. The writing projects
(`journal-paper/`, and in the full-research template `thesis-book/`) are thin layers
that **consume** the outputs produced here.

## What lives where

```
shared-resources/
├── data/         Raw inputs you bring (csv/xlsx/json).  GITIGNORED — never commit raw/credentialed data.
│   ├── DATA_DICTIONARY.md   Describe every variable here.
│   └── ACCESS.md            Where the data came from / how to obtain it (no secrets in git).
├── derived/      Cleaned datasets written by the scripts.  GITIGNORED — regenerated by running scripts.
├── scripts/      The pipeline (run top to bottom):
│   ├── 01-clean.R     raw  -> derived/example-clean.csv
│   ├── 02-analysis.R  derived -> derived/example-stats.csv + example-model.rds
│   └── 03-figures.R   derived -> figures/example-figure.{png,pdf}
├── figures/      Generated plots. The PRODUCER location / single source of truth.  GITIGNORED.
└── references.bib  MASTER bibliography — the single source of truth for citations.  TRACKED.
```

## The three resource types (important asymmetry)

| Resource | Where it lives | How a writing project gets it |
|----------|----------------|-------------------------------|
| **Data** | `data/`, `derived/` | **Read across the boundary by code.** An analysis chunk resolves the programme root from the `.here` sentinel — `root <- rprojroot::find_root(rprojroot::has_file(".here"))` — then reads `file.path(root,"shared-resources","derived","x.csv")`. R/Python read files from anywhere, so this is fine. (We anchor on `.here` rather than `here::here()` because Quarto's `_quarto.yml` makes a writing project look like a `here` root and `here()` would stop there.) |
| **Figures** | `figures/` | **Synced in.** Quarto cannot embed an image outside its own project, so the sync step copies the image file into the writing project before render. |
| **Bibliography** | `references.bib` | **Synced in.** A `bibliography:` file is a Quarto *resource*, same category as an image — so it is copied in, never referenced with `../`. |

Rule of thumb: **code may reach across the folder boundary; Quarto resources (images, .bib) must be synced in.**

## Running the pipeline

From the research-programme root (the folder with the `.here` file), with the shared
`renv` active:

```r
source("shared-resources/scripts/01-clean.R")
source("shared-resources/scripts/02-analysis.R")
source("shared-resources/scripts/03-figures.R")
```

Re-run only when the data or the analysis changes. Rendering the paper or thesis does
**not** run these — that is the whole point: writing renders are fast and never
re-do the slow analysis.

> Tracking policy: `data/`, `derived/`, and `figures/` are **gitignored** — they are
> inputs you supply or outputs you regenerate. `references.bib` and the `scripts/` are
> **tracked**. See the top-level `.gitignore`.
